# AGENTS.md

Guidance for coding agents working in this repository.

## Scope

This is a flake-based, multi-host-ready NixOS and Home Manager configuration.
The active host is `nixbook`: `aarch64-linux` on Apple Silicon/Asahi, with the
COSMIC desktop and Fish shell. The user is `eva`.

## Required validation

Use the path form while newly created files are still untracked; otherwise the
ordinary `.` flake reference is fine.

```bash
nix fmt
nix flake check --no-build --impure path:$PWD
nix build --no-link --impure \
  path:$PWD#nixosConfigurations.nixbook.config.system.build.toplevel
```

The complete check is `nix flake check --impure`. Do not run
`nixos-rebuild switch` unless the user asks to deploy. When requested, the
deployment command is:

```bash
sudo nixos-rebuild switch --flake /home/eva/nixconfig#nixbook --impure
```

`--impure` is required because the Apple Silicon module consumes nixbook's
host-local firmware.

## Architecture

- `flake.nix`: inputs and public outputs only; host declarations call helpers
  from `lib/hosts.nix`.
- `lib/hosts.nix`: NixOS and future nix-darwin constructors. Identity is passed
  in `hostSpec`; do not reintroduce free-form hostname/username arguments.
- `hosts/nixbook/`: host composition, Home Manager composition, and generated
  hardware configuration.
- `profiles/nixos/` and `profiles/home/`: reusable roles composed from modules.
- `modules/nixos/`: focused system features; specialized hardware and apps are
  opt-in from the host.
- `modules/home/`: user-owned programs and configuration.
- `packages/`: custom derivations and shared muvm wrapper logic.
- `overlays/`: custom package exposure and isolated upstream workarounds.
- `themes/`: source theme assets; keep large generated COSMIC trees out of Nix
  expressions.
- `users/`: public identity material only. Never place private keys or secrets
  here.

NixOS and Home Manager modules are plain configuration fragments; this
repository does not currently define a custom option namespace.

## Editing rules

- Never edit `hosts/nixbook/hardware-configuration.nix`; it is generated by
  NixOS. The lint check deliberately excludes it.
- Preserve `system.stateVersion` and `home.stateVersion` unless the user is
  deliberately performing a state migration.
- Put machine identity and hardware in `hosts/`, reusable policy in `profiles/`,
  focused behavior in `modules/`, and packaging mechanics in `packages/` or
  `overlays/`.
- Keep Linux-only Home Manager modules out of OS-neutral profiles so the future
  Darwin path stays usable.
- Custom source pins must include fixed hashes. Document why each override is
  needed and the condition under which it can be removed.
- The firewall is on. New network services must state whether and how they open
  ports.
- `modules/nixos/pynet.nix` is privileged: it grants Python network
  capabilities to the `users` group. Keep it an explicit host opt-in.
- Retain the Asahi cache, low parallelism, 16K-page sysctl, and firmware
  impurity unless a verified platform change makes them obsolete.

## Key exported interfaces

- `lib.mkNixosHost` and lazy `lib.mkDarwinHost`
- `nixosModules` and `homeModules` for reusable profiles/features
- `overlays.default`, `overlays.asahi-apps`, and `overlays.wluma`
- custom `packages.aarch64-linux`
- formatter, lint, and full nixbook checks

See `README.md` for the operator workflow, host-extension recipe, security
notes, and workaround maintenance policy.
